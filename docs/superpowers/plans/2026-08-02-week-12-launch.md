## Task 1: Vercel project setup

- [ ] **Create Vercel project** linked to GitHub repo.

- [ ] **Configure build settings**:
  - Framework preset: Astro
  - Build command: `npm run build`
  - Output directory: `dist/`
  - Install command: `npm ci`

- [ ] **Add environment variables** (Production scope):

  ```
  PUBLIC_SUPABASE_URL          = <prod supabase url>
  PUBLIC_SUPABASE_ANON_KEY     = <prod anon key>
  SUPABASE_SERVICE_ROLE_KEY    = <prod service role>
  PUBLIC_SITE_URL              = https://qayra.in
  RAZORPAY_KEY_ID              = rzp_live_XXXX   (after KYC; rzp_test_ if soft-launching)
  RAZORPAY_KEY_SECRET          = <live secret>
  PUBLIC_RAZORPAY_KEY_ID       = rzp_live_XXXX
  PUBLIC_SENTRY_DSN            = <sentry dsn>
  ```

- [ ] **Preview env vars** — Vercel previews should use test Razorpay + a separate Supabase project if you have one. If not, use the same prod Supabase but with `rzp_test_*`.

- [ ] **Deploy** — push to main, watch Vercel build, verify the `.vercel.app` URL works.

- [ ] **Commit (Vercel config screenshot in README is optional, but commit the deploy badge):**

```powershell
git commit --allow-empty -m "chore: production Vercel project provisioned"
```

## Task 2: DNS cutover to qayra.in

- [ ] **In Vercel project** → Settings → Domains → add `qayra.in` and `www.qayra.in`.

- [ ] **In Cloudflare** (where the DNS for qayra.in lives):
  - **A record:** `qayra.in` → Vercel anycast IPs (`76.76.21.21`) — Proxy status: DNS only (Vercel handles SSL).
  - **CNAME:** `www.qayra.in` → `cname.vercel-dns.com` — DNS only.

- [ ] **Wait for propagation** (usually 5–30 minutes). Vercel will auto-issue Let's Encrypt SSL.

- [ ] **Verify** — `https://qayra.in` loads home page over HTTPS. `https://www.qayra.in` redirects to `qayra.in` (configure in Vercel).

- [ ] **Update Supabase Auth allowed redirect URLs**:
  - In Supabase dashboard → Authentication → URL Configuration:
  - **Site URL**: `https://qayra.in`
  - **Redirect URLs**: add `https://qayra.in/auth/callback`, remove localhost.

- [ ] **Update Google OAuth** — in Google Cloud Console, add `https://<your-project>.supabase.co/auth/v1/callback` to authorized redirects (already there) and `https://qayra.in` to authorized JavaScript origins.

- [ ] **Update Razorpay webhook URL** to `https://qayra.in/api/webhooks/razorpay` (in Razorpay dashboard → Settings → Webhooks).

- [ ] **Commit.**

## Task 6: Soft launch (20 friends/family orders)

- [ ] **Pick 20 trusted people** (family, friends, early supporters).

- [ ] **Send each a personal message** with a 15% off code (created in /admin/discounts as `FRIENDS15`, single-use per customer, expires in 7 days).

- [ ] **Watch the queue daily**. Use the operations dashboard exactly as a stranger would: pack, enter AWB from a real courier (Shiprocket / Delhivery / BlueDart / DTDC — your choice).

- [ ] **After 7 days**, debrief: what broke? What confused them? What did they love? Write findings into `docs/soft-launch-findings.md`.

- [ ] **Hotfix sprint** (3–5 days). Fix anything that came up. Each fix on its own PR with a regression test where reasonable.

## What we EXPLICITLY did NOT do

These remain in **Phase 2** post-launch:

- Email service (Resend) + abandoned cart, reorder, review-request flows
- Analytics (any)
- Mobile OTP auth
- WhatsApp Business API
- GST invoice field at checkout
- Wishlist, gift cards, gift wrap
- Loyalty points, referral program, post-purchase upsell
- Search bar
- Live chat
- Multi-currency, multi-language
- Courier API integration (Shiprocket)
- COD verification queue
- Operations role split from admin (founder is both)
- Subscription / auto-replenish
- `/journal` editorial blog

Each is its own future project; brainstorm + spec + plan when it's time.
